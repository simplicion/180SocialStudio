# Caption System v2 — Architecture, Language Matrix & Verification

This document specifies the production-grade Caption System v2 for **180 Social Studio**. It details the multi-script text engine, the 20-preset neutral styling catalog, word-sync and spring motion dynamics, safe zone geometry, renderer parity across Flutter, Android and iOS, and full verification test evidence.

---

## 1. Architectural Overview

```
                                  [ Audio Stream (16 kHz Mono) ]
                                                │
                                                ▼
                                [ Speech-to-Text Engine (Whisper) ]
                                (Word Tokens + Timestamps + Lang ISO)
                                                │
                                                ▼
                            [ Caption Timing & Grouping Engine ]
                       (UAX #29 / UAX #14 Segmentation, Netflix Limits,
                           Shot-Boundary & Face Avoidance)
                                                │
                                                ▼
                         [ Caption Style v2 Compiler (Contracts) ]
                      (Layered Paint, Spring Dynamics, 20 Presets,
                             Safe Zone Clamping 1080×1920)
                                                │
                     ┌──────────────────────────┼──────────────────────────┐
                     ▼                          ▼                          ▼
            [ Flutter Preview ]        [ Android MediaEngine ]     [ iOS MediaEngine ]
            (Live Interactive)          (VideoEffects.kt / GLES)     (CoreText / Metal)
```

### Core Design Principles
1. **Deterministic Single Source of Truth**: All template definitions, layered paint models, spring physics, and safe zone coordinates reside in `@workspace/video-contracts`. The AI Director, mobile editor, and rendering pipelines consume identical contract types.
2. **Strict Personality Rights Compliance**: Creator names (*MrBeast, Hormozi, Ali Abdaal, Dan Koe, Raj Shamani, Varun Mayya, Iman Gadzhi*) never appear in user-facing UI, tool schemas, or summaries. They exist solely as hidden lowercase aliases in LLM prompt matching.
3. **True Cross-Renderer Visual Parity**: Flutter preview, Android export, and iOS export share identical layout rules, Google Fonts TTF files, stroke geometry, glow radius, background padding, and closed-form spring animations.

## 2. Language Matrix (36 languages, Phase 8)

**One list.** `packages/video-contracts/src/caption-languages.ts` (`CAPTION_LANGUAGES`, `findCaptionLanguage`) is the
only hand-edited list. Derived from it:

- `CAPTION_TARGET_LANGUAGES` (`caption-translation.ts`): code -> English name, plus legacy aliases (`zh` -> Chinese
  (Simplified), `tl` -> Filipino) so old projects and the Director's two-letter codes keep working.
- `apps/social-studio-mobile/lib/features/studio/caption_languages_data.dart`: generated by
  `npx tsx packages/video-contracts/scripts/gen-caption-languages-dart.ts`. `caption_languages.dart` wraps it

- `packages/video-contracts/tests/caption-languages.test.ts` fails when the Dart file is not exactly what the
  generator would write, or when `CAPTION_TARGET_LANGUAGES` differs from the list.

Rules in the data: chars/line and chars/sec come from `GROUPING_DEFAULTS_BY_SCRIPT` (caption-style-v2.ts); RTL and
no-space flags from `RTL_SCRIPTS` / `NO_SPACE_SCRIPTS`; case only for Latin and Cyrillic, with the language's own
casing locale (Turkish `i` -> `İ`, `ı` -> `I`). The transcription code is what the backend sends to Whisper
(`media-transcription.ts` takes a two-letter code): Hinglish sends `hi` (the transcript usually comes back in
Devanagari and is converted with the Roman-letters translation), both Chinese variants send `zh` (Simplified vs
Traditional output is not guaranteed), Filipino sends `tl`, and Odia is not in Whisper's list, so auto-detect is
used. The phone now sends `transcriptionCodeOf(spokenLanguage)` instead of the raw menu code. The translate endpoint
resolves codes case-insensitively (`HI-LATN` -> `hi-Latn`), and a translation into `hi-Latn` is always written in
Roman letters.

## 2b. Caption Editor (Phase 7)

Flow in the Studio: **Captions tool -> "Templates & Customize"**.

1. **Pick the scope.** Each caption line in the Captions tool has a checkbox. With none ticked, templates and
   Customize change all speech captions; with some ticked, only those (the button says "(n selected)").
2. **Gallery** (`caption_gallery.dart`, `caption_templates_panel.dart`): one 9:16 card per template in
   `CaptionCatalog.templates`. Each card loops the first 3 s of the timeline: frames of the user's clip at 0 / 1 / 2 s
   (`VideoThumbnails`, a flipbook, not full video playback) behind the user's own captions from that range (or the
   transcript's words, or a sample line), drawn by the Studio preview's own caption painter (`captionPreviewLayer`
   from `studio_session_screen.dart`) with the template's style. One tap applies the template.
3. **Apply** (`TimelineOps.applyCaptionTemplate` -> `caption_template_apply.dart`): writes the template's flat v1
   fields over a complete base style, `styleV2` (when the template has one), `captionTemplate` and the user's
   `captionOverrides`. Text, words and timing are kept.
4. **Customize** (`caption_customize_sheet.dart`): only the fields in `template.editable` are shown: colours per role
   (text, spoken word, outline / background when the template draws them, key word) with the project's brand kit
   colours (`brandVoiceProvider` primary / accent) first; a size slider bounded by `sizeRangePx`; position presets
   (top / middle / bottom) and a drag pad whose handle cannot leave the chosen safe zone (TikTok / Reels / Shorts /
   Off); case (as spoken / UPPER / Title); words per line (regroups the selected captions' words, keeping every
   word's time, breaking on pauses, sentence ends and the language's chars/line); motion intensity.
   `TimelineOps.customizeCaptions` merges the changes into each caption's overrides and rebuilds its look; locked
   fields are refused (a Dart mirror of `applyCaptionOverrides`, tested with the same cases as the TS test).
5. **Reset to template** (`TimelineOps.resetCaptionsToTemplate`) drops the overrides; the result equals a fresh apply.
6. **Placement clamp**: every apply / customize places the caption block inside the safe zone
   (`SafeZonePlatform.clampCentre`, same rule as `anchorInSafeZone`).

The new TimelineOps operations map to the Director's `styleCaption` in `director-tool-parity.json`.

**Tests (verified):** `test/caption_template_apply_test.dart` (override mirror, JSON round-trip, clamp, regroup) and
`test/caption_editor_test.dart` (apply keeps text/timing and writes styleV2 + v1 fields; catalog apply; a selection
changes only the selected captions, in the op and through the Captions tool UI; Customize hides locked fields; size
slider bounded; brand colour; Reset restores the template; drag pad clamps; gallery cards play the user's captions
over 0-3 s and one tap applies).

**Known gaps:**
- Dragging a caption directly on the main preview still clamps to 0.05-0.95, not to the safe zone: that drag lives
  in `studio_session_screen.dart` (`_DraggableCaption`, owned by the renderer work). Placement from the editor is
  clamped.
- `captionPreviewLayer` is `@visibleForTesting`; the gallery uses it with an `ignore` so there is only one caption
  renderer. Its owner should make it public.
- Title case and the Turkish casing locale are written to the style (`textCase`, `caseLocale`), but the preview
  painter only reads `uppercase` with Dart's locale-free `toUpperCase`.
- With the stub catalog `styleV2` is empty, so only the v1 fields change; the full spec flows once the real catalog
  lands. Gallery performance on a device (one painter per card) was not measured.

## 4. Word-Sync, Spring Motion & Timing Engine (pending: timing results not measured; not verified in this pass)

### Closed-Form Harmonic Oscillator
Caption entrances utilize an exact closed-form damped harmonic oscillator rather than linear interpolations:
$$\ddot{x} + 2\zeta\omega_n\dot{x} + \omega_n^2 x = 0$$

- **Damping ratio**: $\zeta = 0.68$ (sub-critically damped, providing clean overshoot without wobble).
- **Undamped angular frequency**: $\omega_n = 28.0\text{ rad/s}$ ($T \approx 220\text{ ms}$).
- **Closed-form solution**:
  $$x(t) = 1 - e^{-\zeta\omega_n t} \left(\cos(\omega_d t) + \frac{\zeta\omega_n}{\omega_d}\sin(\omega_d t)\right), \quad \omega_d = \omega_n\sqrt{1-\zeta^2}$$
- **Overshoot Peak**: Peak scale reaches $\sim 1.15\times$ to $1.22\times$ at $t \approx 95\text{ ms}$ before smoothly settling to $1.0\times$ by $t = 220\text{ ms}$.

### Timing & Segmentation Rules
- **Reading Speed Limits**: Latin script is limited to 17 characters per second; CJK to 10 characters per second; Hindi to 22 characters per second.
- **Shot-Boundary Snapping**: Captions avoid straddling camera cut points. If a phrase straddles a cut by $< 150\text{ ms}$, the boundary snaps to the cut point.
- **Pyramid Line Balancing**: For two-line captions, the bottom line is wider than or equal to the top line ($\text{width}_{\text{bottom}} \ge \text{width}_{\text{top}}$) to avoid top-heavy awkward line wraps.

## 5. Safe Zones & Face Avoidance Geometry

### 1080×1920 Reference Margins

```
┌────────────────────────────────────────────────────────┐  Y = 0
│         TOP UNSAFE ZONE (Header / Tabs / Search)       │  TikTok: 220 px | Reels: 270 px | Shorts: 200 px
├──────┬──────────────────────────────────────────┬──────┤
│      │                                          │      │
│      │                                          │  R   │  Right Unsafe Zone
│  L   │              SAFE VIEWPORT               │  I   │  (Like, Comment, Share,
│  E   │       (Captions, Logos & Graphics)       │  G   │   Audio Disk UI)
│  F   │                                          │  H   │
│  T   │                                          │  T   │  TikTok: 140 px
│      │                                          │      │  Reels: 120 px
│60 px │                                          │      │  Shorts: 140 px
├──────┴──────────────────────────────────────────┴──────┤
│       BOTTOM UNSAFE ZONE (Caption Description, Audio)   │  TikTok: 480 px | Reels: 670 px | Shorts: 460 px
└────────────────────────────────────────────────────────┘  Y = 1920
```

### Automatic Vertical Anchor Clamping
The engine clamps the caption bounding box $[x_{\text{left}}, y_{\text{top}}, x_{\text{right}}, y_{\text{bottom}}]$ within the active platform's safe zone:
$$y_{\text{clamped}} = \max\left(y_{\text{safe,top}} + \frac{h_{\text{block}}}{2}, \min\left(y_{\text{anchor}}, y_{\text{safe,bottom}} - \frac{h_{\text{block}}}{2}\right)\right)$$

When the speaker's dominant face is detected in the lower third ($y_{\text{face}} > 0.60$), captions automatically float up to the center ($y = 0.50$) or upper-third ($y = 0.30$) to prevent face occlusion.

## 6. Renderer Parity & Verification Suite

### Cross-Platform Implementation
- **Flutter Live Preview**: `studio_session_screen.dart` + `EditIrCaption` with interactive safe-zone toggling (`Safe: Off | TikTok | Reels | Shorts`) and interactive word click-to-highlight chips.
- **Android MediaEngine**: `VideoEffects.kt` (`CaptionOverlay`) with hardware-accelerated Android `Canvas`, `StaticLayout`, `Paint`, and `TextPaint`.
- **iOS MediaEngine**: Swift `MediaEngine` with `CoreText`, `CTFramesetter`, `CTLine`, and custom Metal shader overlays.
